- Host observed: x86_64 workstation, Intel Core Ultra 9 285H, 16 logical CPUs, 30 GiB total RAM. Whether this is the final deployment target remains to be declared.
- Input: authorized CAM-01 recorded clip, SHA-256 `717af2bb3bc3f160dd41ccffebf73b2587dc8093f3f068df3929f7c862b60b8f`, using the approved geometry SHA-256 `8b7ebdbfc5f219f005d098a3b999d9e58b934019ccd733dd47d0bc19b140b24f`. The processed source interval was `[0,15)` seconds. The command used `scripts/process-recorded-clip.py` with `--max-duration-s 15` and was wrapped in `/usr/bin/time -v`.
- Result: exit 0, `processing_mode=online_inference`, three finalized valid windows `[0,5)`, `[5,10)`, `[10,15)`. Their source identity carries the new geometry hash. This is real OpenCV/ITD model processing, not a mock or reference label.
- Process measurements: 14.61 s elapsed wall time, 59.49 s user CPU, 3.39 s system CPU, 430% average CPU utilization, 1,690,104 KiB peak resident memory (about 1.61 GiB), no swaps. These include process startup, model load, video decode, inference, tracking, and finalization; they are **not** isolated inference or state-to-recommendation latency.
