# D01 — decision identity and applied-outcome audit

## Delivered

- Go checks recommendation run, authoritative input session, snapshot sequence, config and metrics versions, model version, forecast origin, pending status, and current `recommend` outcome before exposing or acting on an ID. A source or snapshot change removes the old action from the analysis response; a fresh analysis can create a new action. Late intelligence results cannot overwrite the current epoch.
- Approve and modify fetch and validate the latest simulator state immediately before virtual `ApplyPlan`. A changed source or snapshot returns conflict without dispatching a plan. Existing reason, whole-plan validation, command intent and operator audit paths remain in force.
- `accepted_pending_safe_boundary` leaves the decision intent open. Reconciliation records the simulator's terminal applied/rejected receipt, including the applied virtual tick, in the durable audit and then settles the intent. It never repeats actuation.

## Verification

- Focused regression tests were run RED then GREEN for stale source/snapshot/version rejection, old browser-held IDs, late analysis, latest-state recheck before actuation, and pending-versus-applied intent settlement. The simulator integration test uses gRPC and an isolated PostgreSQL schema; terminal receipt persistence was checked in PostgreSQL.
- Full `go test ./... -count=1` passed against the local PostgreSQL service. Integrated Python, web and contract checks are recorded after merge.

## Remaining limits

- `PlanCommand` does not carry the expected source epoch and snapshot to enforce a simulator-side compare-and-set at dispatch. Go rechecks just before the RPC, and the simulator revalidates at a safe boundary, but an epoch change between those steps still needs C01/S01 contract and runtime work to close the race.
- Snapshot sequence advances with the virtual engine. Strict identity can make an action short-lived until fresh analysis catches up; measure this in Q01 and tune analysis timing without weakening stale approval checks.
- D01 tests establish Go/PostgreSQL/gRPC decision behavior, not the full recorded-video/browser workflow or independent benchmark gates.

Startup reconciliation has no browser actor. `EndInterruptedRun` now assigns the fixed `system-recovery` actor internally; it cannot attribute this system event to a forged or absent request actor.

A subsequent normal full-stack start against the same demo database logged `Reconciled interrupted simulation run` and `Go API ready`; no database reset or volume deletion was used.
