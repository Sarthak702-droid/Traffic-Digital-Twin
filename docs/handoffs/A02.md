# A02 handoff: verified browser session recovery

## Implementation and interface

The A02 implementation was already integrated on `main` at `ce388df` before this handoff. `apps/web/lib/api.ts` sends same-origin cookies to Go, strips browser-supplied actor/role headers, saves a mutation's idempotency key while its outcome is uncertain, and blocks another mutation until review. `apps/web/components/session-panel.tsx` uses the verified `/session` and `/session/login` flows, looks up `/commands/{id}` after sign-in, and never resubmits the uncertain command. Decision drafts are stored under the authenticated actor, run, and recommendation in `apps/web/components/action-rail.tsx`. `scripts/verify-a02-browser.mjs` exercises expiry and re-login in a real Chromium page with mocked API responses.

No public contract or Go API shape changed in this handoff.

## Verification on current main

- `npm run test -w apps/web -- --run components/epic14.test.tsx`: 16 passed. Includes cookie/header, draft persistence, and uncertain-command recovery checks.
- `npm run typecheck -w apps/web`: passed.

## Remaining acceptance boundary

The browser check stubs Go API responses. It confirms browser behavior, not PostgreSQL-backed command persistence or the full Go/Python/browser path. Q01 must exercise expiry and recovery against the real stack. No production deployment or field acceptance is claimed.
