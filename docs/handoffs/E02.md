# E02 partial evaluation handoff — engineering gates remain open

## Files and interface

- `scripts/evaluate-prototype.py` has explicit `--recorded-only` and `--full` modes. `--full` executes the frozen E01 synthetic case matrix and writes one JSON report; both modes keep unrun resource and independent-operator gates visible. The report is local under ignored `.runtime/evaluation/`, not committed.
- `scripts/prototype_evaluation.py` verifies completed observation-bundle bytes and source identity, scores only independently adjudicated reference records with two distinct reviewers, rights and method provenance, and gates recorded forecast scoring on a frozen per-session chronological reserved origin. E01 v1 has no such per-session origin, so its recorded forecast scores correctly remain unavailable.
- The private `Model.rollout` accepts an optional explicit future demand trace only for matched benchmark scoring. The operating analysis path still selects plans from current causal state without that trace. It also returns offered mass and numerical conservation residual. Focused tests verify both behaviors.
- The virtual evaluator uses both configured graphs, three held-out seeds, six conditions and two declared perturbations. Four origins per case compare fixed, per-node local adaptive, and coordinated plans from the same complete state and copied realized demand sequence. `run_virtual_suite` records every failed case instead of dropping it.
