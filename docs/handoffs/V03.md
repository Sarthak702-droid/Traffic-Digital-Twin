# V03 observation API handoff

- **Files:** `apps/api/internal/httpapi/observation_catalog.go`, `observations.go`, `simulation.go`, `server.go`; `apps/api/internal/store/input_binding.go`, `store.go`; migration `008_run_input_binding.sql`; focused API, workflow, and PostgreSQL tests.
- **Interface:** `GET /api/v1/vision/clips` lists processed clip attempts with safe status, source session, hashes, finalized-window timing and completion. `GET /api/v1/observations?camera_id=...&source_session_id=...` serves validated aggregate windows; `as_of_source_s` respects availability and reports stale input. `run_id` resolves the durable source binding and rejects a conflicting source session or changed clip/model/geometry/config/observation digest. Missing input has an empty array, never a fabricated zero. Failed job errors and source paths are not exposed.
- **Run binding:** `POST /api/v1/scenarios/{type}/start` with `demand_source: video_profile` now requires `source_sessions` for every configured boundary camera. Go validates finalized manifests and mapping, persists a fresh `input_session_id` plus full source identities atomically with run creation, and carries the epoch into served state and live subscribers. Reset revalidates the selected identities and creates a new epoch. Seeded runs remain unchanged.
- **Evidence:** Focused RED→GREEN tests cover zero versus missing, checksum damage, duplicate/out-of-order windows, source-time availability/staleness, failed processing, exact boundary selection, run-scoped query mismatch, source replacement, reset epoch, WebSocket state and immutable PostgreSQL binding. `GOCACHE=/tmp/traffic-go-build-cache go test ./...` passed against local PostgreSQL on `127.0.0.1:5433`. An uncommitted one-off Go probe accepted all three existing V01 CAM-01 manifests (2, 6 and 12 finalized windows); it was removed after the check.
- **Next dependency:** F01 must make the Python simulation/intelligence path consume the selected finalized sessions. The current simulation `video_profile` adapter still reads legacy observation files, so this Go binding is not yet proof that a video-backed virtual run used those rows. U01 must let the operator choose the listed source sessions, and D01 must block decisions when bound input becomes unsuitable. Q01 must verify the real Go/PostgreSQL/Python/browser path.
