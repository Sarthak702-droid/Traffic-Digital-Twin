# U01 — operator source, forecast and comparison view

## Delivered

- The WebSocket parser accepts current `1.1` virtual state and preserves run input identity, snapshot, versions, observation history, finalized source time and quality. The REST parser retains forecast method, age, quality, horizon availability, explicit analysis outcome, recommendation identity and matched comparison fields.
- The command center and vision view show display video time, latest completed observation window end, virtual simulation time, forecast origin and data quality separately. Seeded input has no source-video forecast origin. Video selection and seeking are display only, and playback stops at the end rather than looping.
- The browser clears old actions and comparisons when authoritative input changes. It requires current identity for recommendations and matched comparisons, keeps recent non-action analysis visible within the existing ten-second age check, and distinguishes `no_action` from `cannot_evaluate`. The comparison table shows modeled queue delay, boundary exits/backlog, worst service debt and matched window; deprecated individual stops and average delay are not shown.
- Cached observation display requires window end, availability source time and a completed processing timestamp. Valid zero crossings remain visible.

## Verification

- Focused tests were recorded RED then GREEN for the 1.1 WebSocket parser, response field preservation, identity, matched metrics, no-action/cannot-evaluate text, time labels, non-looping display and finalized-window availability. The prior PRD comparison test was updated to the newer prototype metric contract.
- Full web tests, typecheck and Vite build passed in the U01 worktree. A Chromium smoke used an ephemeral hashed operator account against real Go/PostgreSQL/Python/Vite services. It started a seeded peak run, received HTTP 200 from `/api/v1/analysis`, rendered current virtual clocks, opened Vision Analytics, and confirmed media does not loop. Screenshots were captured locally at `/tmp/traffic-u01-browser.png` and `/tmp/traffic-u01-vision.png`. The generated account file was removed, and only PostgreSQL remains running.

## Remaining limits

- The browser smoke used seeded demand. It did not validate fresh recorded-video processing, candidate approval, post-application state or held-out reference measurements; those remain Q01/E02 gates.
- Go currently binds actionable recommendations to an exact one-second snapshot and rejects late intelligence results when a tick advances. In the live seeded browser smoke, `no_action` or `cannot_evaluate` was visible, but no actionable plan was exercised. D01/S03 timing needs a targeted runtime review before claiming the full operator approval workflow.
- The local launcher needed the shared worktree dependencies and a bypass for its stale-process cleanup; its first retry killed the retry shell. P01 should repair worktree startup and measure target-machine capacity.
