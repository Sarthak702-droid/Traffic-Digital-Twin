# S02 — matched virtual network comparison

## Delivered

- Baseline and candidate rollouts use one cloned traffic snapshot, exact road-cell state, boundary backlog, and one finalized-history demand profile. The comparison returns a stable demand-assumptions hash and rejects a conflicting requested horizon or hash.
- Operating schema 1.1 comparisons reject missing cells, mismatched network configuration, missing controlled signal states, or a virtual plan still awaiting activation. Legacy schema 1.0 inputs remain available for older unit fixtures, without an operating-snapshot claim.
- The same 120-second window now reports queue delay (veh·s), boundary exits (veh), end backlog (veh), boundary waiting (veh·s), congested link exposure (link·s), and worst approach service debt (s). Individual average delay and stops are omitted from public JSON because they have no defensible estimator.
- `packages/scenario-config/comparison-scoring-v1.json` declares units and points per unit for normal, emergency-priority, and emergency-recovery cases. The score includes queue delay, boundary wait, exits, spillback exposure, service debt, and timing change. Weights are engineering assumptions pending E01/E02 benchmark evaluation.
- Candidate rollouts use the same virtual boundary guard as the live simulator; a plan that encounters full downstream storage at activation is rejected. The source state is unchanged by comparison.
