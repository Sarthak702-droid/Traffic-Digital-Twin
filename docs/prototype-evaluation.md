# Prototype evaluation protocol v1

**Frozen before held-out execution:** 2026-09-27. Machine-readable constants are in `packages/scenario-config/prototype-evaluation-v1.json`. This document defines E01; it is not an E02 result. Any change to the thresholds, split, perturbations, or reference method after viewing reserved results requires a new protocol version and a new untouched reserved set. Record failed cases, not only aggregate successes.

## Evidence boundaries and input split

The current three five-second candidate windows are in `packages/reference-samples/candidate-windows-v1.json`. CAM-01 ordinary and CAM-05 crowded are tuning; CAM-12 difficult is reserved. Keep source clip and geometry hashes, half-open source times, rights record, observation identity, and independent reviewer records attached to each scored window. Detector predictions and historical `agent_accepted_demo` reports are not reference labels. Do not inspect reserved count or queue answers when tuning geometry, model, thresholds, or protocol. Rights permit internal review per the task record; redistribution is unconfirmed. No reference accuracy score is available until two independent reviewers adjudicate the reserved window.

A window's total crossing-count error is absolute predicted minus adjudicated count; report signed bias, absolute error, and the denominator. The reserved measurement gate requires absolute error at most `max(2 veh, 20% of reference count)`. Score visible queue only if a reviewer marks the same instant and ROI supported; then absolute error must be at most 2 vehicles. Report class counts descriptively, since one small reserved window cannot support a class-level accuracy gate. A missing, invalid, stale, or degraded observation is an explicit failure or unavailable value, never zero. Record processing mode (fresh inference versus valid cache) and source/session hashes. Do not infer speed, corridor coverage, or physical benefit.

For demand forecasts, split each source session chronologically. Tuning forecast origins and all their target intervals end before the first reserved origin; no target interval may cross that boundary. At origin `t`, only finalized windows available by `t` enter either forecaster. Score a horizon only when an actual later finalized target interval exists in the same source session. Report MAE and bias in vehicles separately for 30, 60, 120 and 300 seconds, with eligible origin count, input quality, method, and target type (`independently_reviewed` or `detector_derived`). Persistence repeats the latest eligible window rate. The multi-junction EWMA candidate uses the exact same origins and target intervals. A horizon with fewer than five eligible origins is unavailable for a benchmark claim; software behavior can still be tested on synthetic traces. For scored horizons, aggregate eligible-origin MAE must beat persistence by at least 5%, and no individual horizon may regress more than 10%. If the short clips support none of these horizons, report all recorded-data forecast scores unavailable; do not loop, interpolate future observations, or treat synthetic traces as recorded-data accuracy.

## Virtual model experiment

Use both configured graphs, six hundred virtual seconds per case with the first 120 seconds as warmup. Tuning seeds are 1101, 2202 and 3303. Held-out seeds are 4404, 5505 and 6606. Include peak, off-peak, incident, emergency, degraded-input and no-benefit conditions. Off-peak is a declared lower offered-boundary-demand profile, not a new field scenario. The held-out perturbations scale internal capacities by 0.8 or 1.2, shift valid turning-ratio allocations by ±0.1 followed by normalization at each junction, and scale boundary demand by 1.1 or 0.9. Apply perturbations to the simulated world while preserving each candidate's identical snapshot and offered demand; declare whether the predictor sees nominal or perturbed parameters. Store the exact generated config hashes and seed with each run. If a perturbation makes a graph invalid, report the case invalid and fix the harness without replacing its seed silently.

For every decision origin, clone one complete virtual state, source epoch and demand assumption set. Compare current/fixed timing, documented local adaptive timing (each node responds only to its own approaches), and the coordinated candidate over the same 120-second window. Persistence and local-only forecasting are separate forecast baselines. The fixed baseline retains the configured default green plan. Score the same realized demand sequence and state for all policies. Record queue delay (veh·s), exits (veh), end boundary backlog (veh), integrated boundary wait (veh·s), spillback/congested-link exposure (link·s), worst service debt (s), timing change (s), activation tick and any rejection. Emergency priority and recovery have separate rows, with route service and return-to-normal time; never fold them into an ordinary-score average. Individual vehicle stops and journey time are unavailable model metrics.

A held-out eligible normal/peak/off-peak/incident case counts as an improvement only if coordinated control reduces network queue delay by at least 5% against **both** fixed and local adaptive baselines, while exits fall by at most 2%, boundary backlog and wait grow by at most 2%, spillback exposure grows by at most 2%, and worst service debt grows by at most 10%. Zero baseline values permit no positive regression for that metric. At least half of eligible held-out cases must improve, and every case must report its result even when it regresses. Safety violations or unsafe applied plans allowed: zero. Degraded or unsuitable input must yield zero actionable recommendations. In no-benefit cases, current timing must be retained. Emergency cases must preserve safety and report route/recovery outcomes; an unmeasurable emergency recovery time fails that case rather than being silently omitted. Passing this model gate establishes only a synthetic control result.

Check mass at every tick and at run end: `initial_internal_stock + cumulative_offered_external_demand = current_internal_stock + boundary_backlog + cumulative_boundary_exits`, within 1e-6 vehicle absolute numerical tolerance per link summed across the graph. Offered demand blocked by finite storage remains in backlog. A candidate that reduces central queues while growing boundary or side-road waiting cannot count as an unconditional gain. Record timeout, conflict, stale epoch, manual lock, downstream-full, clearance, and recovery cases as explicit outcomes; retain current timing after failure.

## Resource and operator protocol

The target for this first freeze is the measured Intel Core Ultra 9 285H workstation (16 logical CPUs, 30 GiB RAM). A different deployment target needs a new pre-execution resource freeze. Start one fresh recorded-video job and supported cached boundary inputs, then measure inference including decode and model startup, steady inference throughput, simulation ticks, candidate evaluation, total state-to-recommendation latency, CPU/RAM and finalized-window input age separately. The initial admission limit is one fresh job, with provisional 2 GiB peak RSS and six-core use budgets based on the P01 probe. The candidate deadline is 1.5 s; the state-to-recommendation p95 gate is 5 s, with the desired 2–5 s band. Input age must be at most 10 s for actionable decisions. Do not claim more camera concurrency until measured end-to-end runs meet these limits; an overload must reject or mark input stale rather than silently queueing indefinite work.

An operator who did not implement the pipeline must use `RUNBOOK.md` to register and process the reserved clip, inspect finalized observations and quality, run all three original scenarios on both graphs, take and recover a decision, and export a report. Record command, versions, exit status, screenshots where useful, PostgreSQL/gRPC/OpenCV/browser evidence, and failures. Fresh processing and cache reuse are distinct checks. An independent clip is virtual demand input, not a measured physical corridor. Field validation, live camera operation and physical control remain deferred.
