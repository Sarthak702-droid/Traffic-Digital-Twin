# Versioned contracts

`proto/twin.proto` is the authoritative Go/Python wire model. `typescript/events.ts`, `events.schema.json`, and the protobuf-backed components of `openapi.json` are generated from its descriptor. JSON uses snake_case fields; protobuf int64/uint64 values use strings in JSON to preserve precision. REST network types are in `typescript/network.ts`. All rates use vehicles/minute, queues/capacity vehicles, distances metres, speed km/h, occupancy 0–1 and durations seconds.

WebSocket JSON envelopes use `schema_version`, `sequence` (per connection), RFC3339 `timestamp`, `type` and typed `payload`. Exactly the nine PRD event types are modelled. Epic 1 emits `health.updated`; other producers arrive in their owning epics. Reconnect resets sequence: do not interpret it as a durable audit cursor. Audit REST pagination uses its separate database sequence.

Regenerate with `scripts/generate-contracts.sh`. Tools: protoc-gen-go v1.36.12, protoc-gen-go-grpc v1.6.2 and the Python versions in `services/requirements.lock`. SQL bindings: sqlc v1.30.0, `sqlc generate`.

The functional prototype fields are additive wire shapes defined in `docs/contracts-plan.md` §4. `run-report.schema.json` fixes the public report shape for P02; no report endpoint is claimed by the schema alone. New status vocabularies are constrained in generated JSON schemas. An empty string remains allowed for additive scalar fields when old protobuf JSON prints defaults; runtime validation must reject it for an authoritative prototype run. Their presence in a generated binding does not mean the Go API, Python workers, or browser populate, validate, or persist them yet. C01 tests old-field compatibility and new-field Go/Python round trips; V01/V03/F01/S01/D01/P02 own the corresponding runtime behavior. `apps/api/internal/contracts` and `services/shared/validation.py` enforce the existing state semantics and must be extended by those task owners before the new fields become authoritative.
