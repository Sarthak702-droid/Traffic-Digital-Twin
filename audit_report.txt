2. Supplied Review & Feedback - Complete Baseline
The following section preserves the substance of the review supplied for this audit. It is the baseline against which the repository findings and remediation plan are organized.
The application broadly follows the revised engineering-prototype architecture, but it has not fulfilled the original promise of demonstrably better corridor prediction and control. Concrete safety, data-quality, security, reporting and evidence deviations remain. The review was performed against main at e2afd45 without changing files, configuration, database records or application state. The application stack was not running, so this is not a fresh full-stack acceptance.
Approved scope changes versus the original documents include: real corridor to configured virtual networks; independent recorded clips as declared virtual demand rather than measured physical-junction flow; SUMO/TraCI to finite-capacity aggregate road cells; Go control plane + PostgreSQL + private Python gRPC computation; Next.js to React/Vite; live RTSP, municipal ATCS comparison, physical integration and field calibration deferred; journey time, individual stops, calibrated speed and uncertainty unavailable until defensible estimators/reference data exist; and twelve registered cameras not being evidence of twelve-stream processing capacity.
The important consequence is that the application can demonstrate a virtual decision workflow, but cannot yet substantiate the original real-corridor effectiveness claims.
Highest-priority findings: the required control benefit has failed its predefined benchmark; manual takeover or a new lock can leave an already approved plan scheduled to apply; manual reconciliation can settle a pending decision without establishing actual outcome; command identity is optional and does not robustly distinguish operations; forecasting confuses finalized-window end with availability time; and the delivery dashboard can read outside its evidence directory.
Other deviations: configured departing counts are incorrect or insufficiently validated; corrupt/truncated decoding can be reported as successful; queue estimation depends on pixels per sampled frame rather than elapsed source time; operating prediction snapshots omit known unreleased demand commitments; comparison computation bypasses analysis admission/deadline controls; established WebSocket connections do not recheck expired/revoked sessions.
UI, privacy and evidence drift: old recorded flow can remain displayed after coverage ends; Mean Headway and individual passage events are reconstructed from sample changes and are not defensible individual measurements; tracking IDs/trails are persisted despite the aggregate-only privacy boundary; reference-quality claims are generated from literals rather than independent review; presentation-specific assumptions remain (exactly twelve cameras, two controlled junctions, C3/C1 legacy assumptions); completion claims can contradict current readiness; and clean installation instructions omit vision-specific dependencies.
The core architecture, server-derived identity, aggregate backlog preservation, configured graphs, matched comparisons, explicit replay, virtual scheduler application and authenticated durable report export are present. However, six acceptance gates remain open or failed: access/claims; forecasts; safe control; recorded measurements; benchmarks; and packaging/operation. The most consequential remaining work is safe operator authority, truthful evidence and proof that coordinated control actually helps.
3. Scope Changes That Are Not Defects
Real physical corridor -> configured virtual networks. Independent clips provide declared demand, not measured inter-junction flow.
SUMO/TraCI -> finite-capacity aggregate road-cell simulation.
Public Python API concept -> Go public control plane, PostgreSQL persistence, private Python gRPC compute.
Next.js -> React/Vite frontend.
Live RTSP, municipal ATCS comparison, physical-controller integration and field calibration -> later phase.
Journey time, individual stops, calibrated speed and uncertainty -> intentionally unavailable until defensible.
Twelve-camera registry -> inventory only; it does not prove twelve-stream real-time capacity.
Interpretation rule  
Do not file the approved architecture changes above as defects. File defects only where the implementation violates the revised authoritative plan, safety/evidence boundaries, or acceptance criteria.

01. Control benefit benchmark failed

02. Manual takeover / lock does not invalidate a pending plan
● CRITICAL
 SAFETY 
 CONTROL 
WHERE
apps/api/internal/httpapi/decision.go; mode/lock handlers; simulator scheduler/activation guard
EVIDENCE / ISSUE
Approval can dispatch a plan that waits for a safe boundary. Mode/lock changes update Go/PostgreSQL state, but no authoritative cancellation/revision is propagated to invalidate the pending simulator plan.
WHY IT MATTERS
Operator intent can be overridden after manual takeover or after a phase is locked. This is a control-authority violation.
EXACT FIX
Introduce a simulator-owned control authority revision (control_epoch / lock_revision). Bind every PlanCommand to expected authority, mode and lock revision. Increment revision on manual takeover or lock mutation; cancel pending plans or fail activation if revisions differ. Activation guard must recheck current mode/locks under the simulator lock.
DONE / ACCEPTANCE TEST
Regression: approve plan -> before activation switch to manual or add conflicting lock -> advance through activation boundary -> plan must not apply; durable audit must record cancelled/invalidated outcome.
approve plan -> accepted_pending_safe_boundary
operator switches MANUAL / adds lock
old plan reaches activation boundary
REQUIRED: authority revision mismatch -> cancel / reject activation
03. Manual reconciliation can settle without actual outcome
● CRITICAL
 SAFETY 
 AUDIT 
WHERE
apps/api/internal/httpapi/decision.go; apps/api/internal/httpapi/reconcile.go; decision_intents persistence
EVIDENCE / ISSUE
Manual resolve can mark an intent settled without requiring a simulator receipt, current scheduler-state proof, or cancellation acknowledgement. Browser-supplied recommendation identity is also accepted.
WHY IT MATTERS
A plan may later apply after the intent was removed from automatic reconciliation, breaking terminal audit/recovery guarantees.
EXACT FIX
Make server derive recommendation/run identity from the durable intent. Permit terminal settlement only as CONFIRMED_APPLIED or CONFIRMED_NOT_APPLIED with evidence. Keep UNKNOWN unresolved. Add explicit CancelPlan/QueryCommandOutcome semantics or prove current scheduler state before settlement.
DONE / ACCEPTANCE TEST
Create uncertain ApplyPlan outcome; call resolve without receipt -> must remain unresolved. After simulator confirms applied/not-applied -> settlement succeeds and report contains evidence link/receipt hash.
04. Idempotency key is optional in practice
● CRITICAL
 SECURITY 
 RELIABILITY 
WHERE
apps/api/internal/httpapi/idempotency.go
EVIDENCE / ISSUE
Missing, too-short or too-long Idempotency-Key falls through to next handler instead of rejecting the state-changing command.
WHY IT MATTERS
Retries, double clicks and uncertain network outcomes can create duplicate or ambiguous mutations despite the API claiming idempotent commands.
EXACT FIX
For every mutating route require a valid key. Missing/malformed -> 400; reservation store unavailable -> 503. Never execute a protected mutation outside reservation. Define a canonical command envelope and retain command lookup across session expiry/re-login.
DONE / ACCEPTANCE TEST
For each mutating endpoint: no key, malformed key, duplicate valid key, same key/different payload, reservation-store outage. Only first valid identical command may execute.
05. Command identity is not strongly operation-bound
● HIGH
 SECURITY 
WHERE
apps/api/internal/httpapi/idempotency.go; command_outcomes store/writer
EVIDENCE / ISSUE
Middleware hashes body bytes; route is passed separately and method is not visibly cryptographically bound into the hash. Exact mismatch handling therefore depends on persistence semantics.
WHY IT MATTERS
Cross-operation key reuse can become ambiguous and is harder to reason about/audit.
EXACT FIX
Hash canonical envelope: actor/session scope + HTTP method + normalized route template + canonical body + API command version. Store and compare all identity fields. Reuse with any mismatch -> 409 conflict.
DONE / ACCEPTANCE TEST
Reuse same key across POST mode, DELETE lock, and same route with changed body. Every non-identical operation must be rejected; exact retry must return original receipt.
06. Forecast watermark uses wrong time semantic
● CRITICAL
 FORECAST 
 DATA QUALITY 
WHERE
services/intelligence/forecast_demand.py; traffic-state snapshot construction
EVIDENCE / ISSUE
Forecaster compares observation available_at_source_s against latest_finalized_window_end_source_s. A [0,5) window becoming available at source second 6 can be rejected at a second-6 snapshot because 6 > 5.
WHY IT MATTERS
Valid delayed observations disappear from forecasting; forecasts can become missing or lag behind actual available evidence.
EXACT FIX
Carry separate finalized evidence watermark and availability/snapshot watermark. Eligibility should require window_end <= finalized boundary and available_at <= snapshot availability time. Add explicit processing-age field and cached/fresh semantics.
DONE / ACCEPTANCE TEST
Unit cases: available exactly at end, one second late, much later, and future availability. Late-but-available evidence must be accepted; look-ahead must remain impossible.

08. Departing-direction counts are not proven correct
● HIGH
 DATA QUALITY 
 VISION 
WHERE
services/vision/itd_pipeline.py; services/vision/recorded_clip.py; camera geometry/config tests
EVIDENCE / ISSUE
The data model/config supports approaching/departing, but the authoritative event acceptance/output semantics are not backed by a complete direction inversion regression matrix. Review identified risk of accepting only one crossing sense while labelling output with configured direction.
WHY IT MATTERS
Departing cameras can produce wrong-direction counts or false zeros, corrupting boundary demand.
EXACT FIX
Make crossing direction an explicit computed value independent of label. Compare computed direction to configured primary_direction before aggregation. Add mirrored synthetic trajectories and real reviewed samples for both directions.
DONE / ACCEPTANCE TEST
Four mandatory tests: approaching->approaching count; approaching->departing zero; departing->departing count; departing->approaching zero. Verify class and lane aggregation too.
09. Truncated/corrupt decode can be published complete
● HIGH
 DATA QUALITY 
 EVIDENCE 
WHERE
services/vision/itd_pipeline.py; services/vision/recorded_clip.py; compare scripts/prepare-reference-review.py
EVIDENCE / ISSUE
Authoritative loop treats cap.read() failure as break/EOF. A separate review script correctly raises when a clip ends early, showing the stronger pattern already exists.
WHY IT MATTERS
Partial evidence can be cached and treated as complete, creating silent data loss and misleading provenance.
EXACT FIX
Track requested source interval, expected duration/frame count, last decoded source timestamp and decoder errors. Publish complete only when requested coverage is reached within tolerance. Otherwise incomplete_decode/error and never eligible for authoritative cache reuse.
DONE / ACCEPTANCE TEST
Use truncated file, corrupt middle frames, zero-frame file, valid EOF, requested sub-range. Only valid full coverage may publish complete manifest.
10. Queue estimator depends on pixels/sample cadence
● HIGH
 VISION 
 DATA QUALITY 
WHERE
services/vision/itd_pipeline.py queue/motion logic; camera geometry
EVIDENCE / ISSUE
Fixed pixel motion thresholds change meaning with resolution, perspective, source FPS and inference sampling interval.
WHY IT MATTERS
Same traffic can be classified differently after resize or sampling changes; queue values are not stable measurements.
EXACT FIX
Use normalized displacement divided by elapsed source time; normalize by frame dimension and, where available, perspective/ROI scale. Keep metric explicitly visible-region estimate. Calibrate thresholds per geometry and preserve sampling metadata.
DONE / ACCEPTANCE TEST
Replay same reviewed segment at multiple inference FPS/resolutions. Queue classification should remain within declared tolerance and must not change solely because sampling interval changes.
11. Prediction snapshot omits known unreleased demand commitments
● HIGH
 FORECAST 
 MODEL 
WHERE
simulation/intelligence snapshot and rollout demand construction
EVIDENCE / ISSUE
For remaining mass of already available bins, rollout can substitute forecast rates instead of preserving known commitments from the complete snapshot.
WHY IT MATTERS
Projection semantics diverge from the authoritative state even if candidate comparisons remain internally matched.
EXACT FIX
Represent known committed-but-unreleased demand separately from unknown future demand. Consume committed mass first; forecast begins only after known evidence horizon. Include both in demand-assumptions hash.
DONE / ACCEPTANCE TEST
Construct snapshot with partially consumed finalized bin. Baseline/candidate rollouts must release exactly the remaining committed mass before forecast mass.
12. Compare bypasses analysis admission/concurrency controls
● HIGH
 RELIABILITY 
 CONTROL 
WHERE
services/intelligence/service.py Compare; shared analysis admission/deadline mechanism
EVIDENCE / ISSUE
Compare directly calls model.comparison while Analyze is the path associated with bounded analysis controls. Caller timeout alone is not server admission control.
WHY IT MATTERS
Repeated simulations/modify/approval rechecks can exceed declared compute budget and degrade control responsiveness.
EXACT FIX
Create one shared admission controller for Analyze, Compare and any expensive Predict path: semaphore/queue, per-request deadline, candidate/horizon budget and cancellation propagation. Return RESOURCE_EXHAUSTED/DEADLINE_EXCEEDED with no actionable recommendation.
DONE / ACCEPTANCE TEST
Saturate configured concurrency then issue Compare. Excess request must be rejected/queued per policy, not execute unbounded. Verify cancellation stops work.
13. WebSocket sessions are authenticated only at upgrade
● HIGH
 SECURITY 
WHERE
Go WebSocket upgrade/stream loop; session store
EVIDENCE / ISSUE
REST can revalidate each request, but an already-upgraded stream can continue after session expiry/revocation unless the connection loop checks it.
WHY IT MATTERS
Logged-out/revoked users can continue receiving operational telemetry.
EXACT FIX
Bind stream to session ID + expiry. Close at expiry and periodically check revocation/version. Password reset/session revoke should actively or promptly terminate associated streams. Use explicit close code/reason.
DONE / ACCEPTANCE TEST
Open stream, revoke session, verify stream closes within bounded interval and no later events arrive. Repeat for natural expiry and account reset.

9. Engineering Decision: Definition of Done for the Next Milestone
NEXT MILESTONE  
An operator-approved coordinated plan must never execute after control authority changes, and on a frozen untouched benchmark the coordinated controller must demonstrably outperform both fixed and local-adaptive baselines without shifting unacceptable congestion, backlog, spillback or service debt elsewhere.
This milestone deliberately combines the two highest-value dimensions: safe operator authority and demonstrated control benefit. UI expansion, additional presentation features, and broader camera inventory should not take precedence over these gates.
